The pitch · model additions and tradeoffs

This direction protects creative work from becoming an hours competition. Pair a time commitment with a named deliverable and a specific next action.

Existing projects have labels and notes; project logs have project relationships and intervals. Tasks already support task/project-id, task/state, and task/done-at. Reuse tasks for next actions before inventing a milestone subsystem.

Add optional project-log/activity-id referencing an activity such as writing, drawing, music, software, or editing. A project/activity-id can supply a default, copied onto new logs. Never recategorize old sessions merely because a project default changes.

Add optional task/milestone to distinguish deliverables. Existing task/state and task/done-at already support completed milestones and their dates. Use project-log notes for output descriptions first. Defer words, sketches, and tracks as structured quantities until you actually want a numeric output goal.

Violet distinguishes the studio from training. The same spacing, panels, and numeric hierarchy keep it recognizably Gleanmo. Future attribution charts fit ECharts stacked bars; these HTML bars keep the exploration offline.
